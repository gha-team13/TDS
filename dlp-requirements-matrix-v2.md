# Enterprise DLP Requirements Matrix & Architecture Specifications (v2)

This document synthesises the business and functional requirements extracted from the enterprise Data Loss Prevention (DLP) architecture JAD sessions and requirements-gathering transcripts. This updated version incorporates **humanised, real-world examples** written in plain language for business stakeholders.

## Output 1: Business Requirements

| Category | Business Requirement | Business Outcome | Real-World Example |
| :--- | :--- | :--- | :--- |
| Email DLP | Establish secure, authenticated connectivity and onboarding pathways for low-environment and production Email DLP tenant URLs. | Ensures administrative readiness and secure platform management, preventing unauthorised access during tenant onboarding. | A security administrator sets up a isolated sandbox environment to safely test out new email rules without risking any disruption to the live production email flow. |

| Email DLP | Implement reliable, high-speed routing and error handling for outbound email delivery failures and Non-Delivery Reports (NDRs). | Ensures immediate administrative visibility into delivery failures and prevents data leakage through misrouted bounce-back notifications. | A user typos a client's email address when sending a proposal. | Cloud DLP (CASB) | Integrate third-party file sensitivity labels (Microsoft Information Protection - MIP) within the cloud DLP scanner and detector logic. | Leverages existing enterprise classification investments to ensure files with pre-existing labels are automatically protected in the cloud. | A financial analyst saves a spreadsheet as 'Confidential' using Microsoft Office's built-in labels. | Cloud DLP (CASB) | Protect highly sensitive proprietary assets and intellectual property (IP) using digital asset indexing or document matching. | Prevents exfiltration of exact or partial proprietary files while maintaining platform performance and preventing stability degradation. | A product designer tries to upload a copy of a highly confidential blue-print file to a personal cloud storage folder. The system recognizes the unique digital fingerprint of the file and immediately stops the upload. |
| Cloud DLP (CASB) | Ensure secure, audited integration of Active Directory and Entra ID cloud identities with Cloud DLP modules. | Provides accurate user contextual mapping to cloud security events under a strict, least-privilege administrative model. | A security investigator looks into an alert showing that 'John Doe' uploaded a sensitive project plan to a shared public folder. | Cloud DLP (CASB) | Incorporate automated, script-based configuration migration pipelines across DEV, PAT/PAD, and Production environments. | Minimizes manual coordination effort, shortens deployment timelines, and ensures only thoroughly tested policies are promoted. | A security engineer designs a new cloud storage policy, tests it in the development environment, and uses an automated script to push it to production without having to manually copy and paste dozens of settings. |
| Cloud DLP (CASB) | Enforce strict security controls on Single Sign-On (SSO) credentials and developer portal access inside the cloud DLP tenant. | Prevents unauthorized administrative access and protects sensitive integration secrets (Client IDs/Secrets) from plain-text exposure. | A developer logging into the API management portal must use multi-factor authentication (MFA) to access their developer keys, ensuring their administrative rights aren't stolen or exposed. |
| Cloud DLP (CASB) | Establish robust, geofenced user catalogs and regional cloud routing to satisfy strict data residency compliance. | Adheres to regional privacy laws (e.g., GDPR, CCPA) by ensuring user data is scanned and stored within mandated geographical boundaries. | Under GDPR guidelines, European employees' cloud storage interactions must be routed and scanned by a server physically located within the EU, ensuring their personal data never leaves European borders. |
| Cloud DLP (CASB) | Monitor and prevent accidental sharing or uploading of sensitive corporate files to sanctioned and unsanctioned cloud platforms. | Reduces the risk of data exposure on public folders or personal repositories like OneDrive, SharePoint, or Dropbox. | An employee tries to upload a list of customer credit card numbers to a personal Dropbox account instead of the official company OneDrive. The system detects the personal account and blocks the upload. |
| Endpoint DLP | Monitor and restrict sensitive data exfiltration through physical endpoint channels such as local printers, faxes, and removable USB drives. | Secures the physical perimeter, preventing local exfiltration of customer PII or confidential spreadsheets. | A customer service agent plugs in a personal USB thumb drive and tries to copy an Excel file containing customer database records. The system blocks the transfer and logs the attempt. |
| Endpoint DLP | Bind data protection policies and rules to human identities rather than physical endpoint devices. | Ensures consistent policy enforcement across multiple user devices and prevents gaps when users switch workstations. | When an employee switches from their desktop PC to their corporate laptop, the same strict DLP rules (like blocking copy-to-USB) follow them automatically because the policy is tied to their username, not the machine. |
| Endpoint DLP | Incorporate Insider Threat Management (ITM) visual screenshot capture for high-risk data interactions on user endpoints. | Provides security investigators with visual forensic evidence to validate, reconstruct, and confirm suspicious endpoint activity. | A user is caught trying to mass-download confidential source code files. The ITM agent immediately starts taking screenshots of their screen, giving investigators visual proof of the activity. |
| Endpoint DLP | Distinguish continuous raw endpoint metadata logging from high-priority, rule-triggered prevention alerts. | Enables exhaustive forensic investigations through an endpoint activity timeline while preventing SOC analyst fatigue from alert noise. | While the system silently logs that a user is simply renaming files or browsing folders for future forensic investigation, it only sends an active alert to the security team when they attempt to copy a confidential file to a personal drive. |
| Endpoint DLP | Deploy real-time, interactive end-user prompts and educational warnings to capture business justifications during risky file movement. | Educates employees in real-time, reduces accidental policy violations, and records user-provided business justifications for audit compliance. | A worker tries to move a large file to a shared folder. A small pop-up window appears on their screen, saying: 'This file contains customer data. Please provide a brief business reason for moving this file to complete your action.' |
| Endpoint DLP | Enforce endpoint-level whitelisting and application control over desktop software interacting with corporate data. | Restricts unauthorized applications (such as personal chat utilities or untrusted software) from accessing or moving sensitive files. | The system prevents a user from opening corporate client spreadsheets inside a personal, unapproved file-sharing app (like WeChat or Discord) installed on their desktop, while allowing it in Microsoft Excel. |
| Endpoint DLP | Maintain continuous, stable endpoint agent communications and telemetry flow with the central management platform. | Eliminate blind spots in endpoint monitoring caused by silent agent connection drops or service failures. | The IT department receives an automated alert when an executive's laptop stops checking in with the security console for several weeks, triggering a service check to ensure their agent is still actively protecting their files. |
| Endpoint DLP | Enforce custom Smart ID detectors on local endpoints to block the exfiltration of cryptographic files and private certificates. | Prevents high-risk breaches involving compromised private PKI keys and certificates directly from user endpoints. | An administrator tries to copy a private SSL key file (like '.pem' or '.key') onto an external drive. The local endpoint agent scans the file's contents, identifies it as a cryptographic key, and blocks the action. |
| Endpoint DLP | Align endpoint agent installation requirements with existing local antivirus (AV) and host-level security configurations. | Ensures uninterrupted agent performance, prevents endpoint CPU degradation, and avoids security software conflicts. | During deployment, the security team ensures the new DLP software doesn't conflict with Windows Defender, preventing the computer's CPU from spiking to 100% and slowing down the employee's work. |
| Endpoint DLP | Establish a structured, monitor-only testing phase before deploying active blocking rules across production endpoints. | Enables the security team to establish behavioral baselines, tune rules, and validate stability before affecting user workflows. | The DLP system is installed on 100 employee computers in 'monitor-only' mode for the first month to observe normal workflows and eliminate false alarms before the 'blocking' rules are turned on. |
| Web DLP | Monitor and prevent unauthorized exfiltration of sensitive files and PII via browser-based web uploads. | Prevents accidental or malicious data uploads to unsanctioned websites, personal webmail, or external job boards. | An employee opens their personal Gmail account in Google Chrome and tries to attach a confidential company financial report. The system scans the attachment in real-time and blocks the upload. |
| Web DLP | Prevent exfiltration of sensitive corporate data, source code, or PII through Generative AI (GenAI) prompt text submissions. | Mitigates compliance and intellectual property exposure resulting from employees typing proprietary text into public GenAI platforms (e.g., ChatGPT). | A software developer pastes a block of proprietary source code or customer account numbers into ChatGPT to help debug it. The system detects the sensitive data and prevents the text from being submitted. |
| Web DLP | Mitigate data exfiltration through alternative browser features or side-channels that bypass standard endpoint monitors. | Closes browser loopholes (such as the Microsoft Edge sidebar) before go-live, ensuring a secure browser perimeter. | A user opens a confidential PDF in Microsoft Edge and tries to upload it to their personal OneDrive using the browser's built-in sidebar. The system recognizes the sidebar action and blocks the file transfer. |
| Web DLP | Restrict administrative and developer portal access through role-based inline authentication and adaptive access controls. | Protects the integrity of the DLP platform's administrative settings and restricts developer portal configurations to authorized roles. | An employee clicks a link to open the DLP developer configuration portal. Because they are not an approved security admin, the system blocks their access, requiring they log in with a verified, role-authorized account. |
| Web DLP | Govern browser extension deployments through controlled, enterprise-approved software distribution channels. | Prevents manual or ad-hoc user installations and ensures a standardized, tested browser-DLP extension across the enterprise. | The company uses an automated tool to push the Proofpoint Chrome extension to all user computers, preventing employees from manually turning off or uninstalling the extension to bypass web filters. |
| Web DLP | Ensure resilient, uninterrupted administrator platform access during Single Sign-On (SSO) failures. | Provides a secure, vaulted 'break-glass' bypass mechanism for emergency administrators to resolve SAML and SSO certificate issues. | If the company's main login system goes down, security managers can still access the DLP administrative panel using a highly secure, offline 'break-glass' account to fix the settings. |

## Output 2: Functional Requirements & Specifications

| Category | Requirement | Specification | Real-World Example |
| :--- | :--- | :--- | :--- |
| Email DLP | Outbound Microsoft 365 User Mail Flow Routing | The system must route all outbound user email from Microsoft 365 through the Email DLP pod prior to final internet delivery. This routing configuration is handled by the **DPEML** component. | An employee sends an email to an external vendor. Behind the scenes, Microsoft 365 automatically redirects the message to Proofpoint first to scan for sensitive data before it actually leaves for the internet. |
| Email DLP | Application-Generated and Transactional Email Routing | The platform must establish dedicated relay routing for application-generated mail flows (AppRelay, UMP) through the Email DLP pod. Handled by the **DPEML** component. | The automated payroll system sends out monthly pay slips. This bulk system-generated email traffic is routed through a dedicated Proofpoint channel so it doesn't get slowed down by normal employee email traffic. |
| Email DLP | Differentiated Rules and Dispositions for User vs. Application Mail | The platform must apply different enforcement rules based on mail type, allowing user-sent mail to be blocked or encrypted, while application-generated mail is set to audit-only or alternate dispositions. Handled by the **DPEML** component. | If an employee tries to email a spreadsheet of social security numbers, they are blocked. But if the automated, verified system emails the same type of data to an authorized financial partner, the system allows it through as a verified business exception. |
| Email DLP | Outbound Email Encryption Triggers | The system must trigger the Proofpoint Encryption module based on the subject line keyword (e.g., '[Encrypt]', '[Secure]'), email body, x-headers, or upstream application tags. Handled by the **DPEML** component. | An HR specialist types '[Secure]' in the subject line of an email containing a job offer, which triggers the system to automatically encrypt the email so only the recipient can safely open it. |
| Email DLP | DLP-Driven Outbound Message Encryption Tagging | The email gateway must accept and act on a DLP-applied header indicating encryption is required, or configure DLP rules to invoke the encryption module directly before delivery. | Email DLP | Non-Delivery Report (NDR) and Bounce Routing Mapping | The gateway must process 500-level fatal errors and route NDRs to the envelope sender 'Return-Path' rather than the display 'From' address, executing notifications within a 3-minute threshold. | Email DLP | Legacy Application Port 587 Redirection | The system must support legacy email clients on Port 587 by configuring network firewall port-forwarding to redirect Port 587 traffic to standard Port 25 before MTA inspection, maintaining RFC compliance. Handled by the **DPEML** component. | An old corporate mainframe application is hardcoded to send automated emails using standard Port 587. The firewall intercepts this and forwards it to Port 25, allowing Proofpoint to scan it for data loss without breaking the legacy system. |
| Email DLP | MTA Real-Time Admin Queue Monitoring | The platform must provide real-time administrative visibility into the mail queue to search, filter, and track message status (accepted, queued, or bounced) by return path. Handled by the **DPEML** component. | A security manager logs into the dashboard to check if a critical, high-value outbound email is stuck, easily finding its status by searching the sender's return path. |
| Email DLP | Cross-Platform Newly Registered Domain (NRD) Policy Tuning | The system must deploy Proofpoint NRD rules in monitor/audit-only mode, compare detection logs against Microsoft Defender to identify policy overlap, and configure exceptions to prevent redundant blocking. | Cloud DLP (CASB) | Microsoft Information Protection (MIP) Metadata Reading | The cloud scanning engine must inspect file metadata and perform exact or keyword matching against MSIP sensitivity labels (MSIP_Label, MSIP_Label_GUID, MSIP_Label_Name).
