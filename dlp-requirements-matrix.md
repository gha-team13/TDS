# Enterprise DLP Requirements Matrix & Architecture Specifications

This document synthesises the business and functional requirements extracted from the enterprise Data Loss Prevention (DLP) architecture JAD sessions and requirements-gathering transcripts. The requirements are categorised into the four core DLP pillars and mapped to the respective technical enforcement components: **DPSEC** (File/Endpoint/Data-at-Rest DLP) or **DPEML** (Email DLP).

## Output 1: Business Requirements

| Category         | Business Requirement                                                                                                                                                 | Business Outcome                                                                                                                                             |
|:-----------------|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Email DLP        | Establish secure, authenticated connectivity and onboarding pathways for low-environment and production Email DLP tenant URLs.                                       | Ensures administrative readiness and secure platform management, preventing unauthorised access during tenant onboarding.                                    |
| Email DLP        | Secure outbound user and application-generated email flows (AppRelay, UMP) while maintaining differentiated rule enforcement policies.                               | Protects outbound corporate email communications from accidental PII/sensitive data leakage while ensuring transactional application mail remains unblocked. |
| Email DLP        | Support both user-triggered and automated system/DLP-triggered email encryption workflows for outgoing communications.                                               | Mitigates the risk of employee negligence by automatically or manually securing sensitive datasets before they leave the enterprise network.                 |
| Email DLP        | Maintain strict sender authentication and domain alignment while permitting legitimate user-facing customized display 'From' headers (vanity senders).               | Prevents spoofing and ensures outbound emails meet security standards (SPF/DKIM) without disrupting business lines using vanity sender addresses.            |
| Email DLP        | Implement reliable, high-speed routing and error handling for outbound email delivery failures and Non-Delivery Reports (NDRs).                                      | Ensures immediate administrative visibility into delivery failures and prevents data leakage through misrouted bounce-back notifications.                    |
| Email DLP        | Modernize gateway threat protection by actively intercepting outbound mail and supporting retroactive mailbox cleaning mechanisms.                                   | Enables proactive interception of sensitive data and supports automated, retrospective extraction of malicious or non-compliant emails from user inboxes.    |
| Email DLP        | Support legacy internal software systems and applications routing email traffic over non-standard outbound ports (Port 587).                                         | Maintains operational continuity for legacy systems while ensuring outbound traffic is subjected to complete DLP scanning.                                   |
| Email DLP        | Deconflict overlapping email security policies between Proofpoint controls and existing security frameworks (such as Microsoft Defender/Exchange Online Protection). | Eliminates administrative redundancy, reduces system overhead, and avoids rule collision or false-positive email blocks.                                     |
| Cloud DLP (CASB) | Implement continuous Data Security Posture Management (DPSPM) to scan cloud-based databases, file shares, and cloud storage repositories.                            | Provides complete visibility into data-at-rest security risks, mapping file ownership and identifying over-permissive sharing in cloud environments.         |
| Cloud DLP (CASB) | Integrate third-party file sensitivity labels (Microsoft Information Protection - MIP) within the cloud DLP scanner and detector logic.                              | Leverages existing enterprise classification investments to ensure files with pre-existing labels are automatically protected in the cloud.                  |
| Cloud DLP (CASB) | Protect highly sensitive proprietary assets and intellectual property (IP) using digital asset indexing or document matching.                                        | Prevents exfiltration of exact or partial proprietary files while maintaining platform performance and preventing stability degradation.                     |
| Cloud DLP (CASB) | Ensure secure, audited integration of Active Directory and Entra ID cloud identities with Cloud DLP modules.                                                         | Provides accurate user contextual mapping to cloud security events under a strict, least-privilege administrative model.                                     |
| Cloud DLP (CASB) | Incorporate automated, script-based configuration migration pipelines across DEV, PAT/PAD, and Production environments.                                              | Minimizes manual coordination effort, shortens deployment timelines, and ensures only thoroughly tested policies are promoted.                               |
| Cloud DLP (CASB) | Enforce strict security controls on Single Sign-On (SSO) credentials and developer portal access inside the cloud DLP tenant.                                        | Prevents unauthorized administrative access and protects sensitive integration secrets (Client IDs/Secrets) from plain-text exposure.                        |
| Cloud DLP (CASB) | Establish robust, geofenced user catalogs and regional cloud routing to satisfy strict data residency compliance.                                                    | Adheres to regional privacy laws (e.g., GDPR, CCPA) by ensuring user data is scanned and stored within mandated geographical boundaries.                     |
| Cloud DLP (CASB) | Monitor and prevent accidental sharing or uploading of sensitive corporate files to sanctioned and unsanctioned cloud platforms.                                     | Reduces the risk of data exposure on public folders or personal repositories like OneDrive, SharePoint, or Dropbox.                                          |
| Endpoint DLP     | Monitor and restrict sensitive data exfiltration through physical endpoint channels such as local printers, faxes, and removable USB drives.                         | Secures the physical perimeter, preventing local exfiltration of customer PII or confidential spreadsheets.                                                  |
| Endpoint DLP     | Bind data protection policies and rules to human identities rather than physical endpoint devices.                                                                   | Ensures consistent policy enforcement across multiple user devices and prevents gaps when users switch workstations.                                         |
| Endpoint DLP     | Incorporate Insider Threat Management (ITM) visual screenshot capture for high-risk data interactions on user endpoints.                                             | Provides security investigators with visual forensic evidence to validate, reconstruct, and confirm suspicious endpoint activity.                            |
| Endpoint DLP     | Distinguish continuous raw endpoint metadata logging from high-priority, rule-triggered prevention alerts.                                                           | Enables exhaustive forensic investigations through an endpoint activity timeline while preventing SOC analyst fatigue from alert noise.                      |
| Endpoint DLP     | Deploy real-time, interactive end-user prompts and educational warnings to capture business justifications during risky file movement.                               | Educates employees in real-time, reduces accidental policy violations, and records user-provided business justifications for audit compliance.               |
| Endpoint DLP     | Enforce endpoint-level whitelisting and application control over desktop software interacting with corporate data.                                                   | Restricts unauthorized applications (such as personal chat utilities or untrusted software) from accessing or moving sensitive files.                        |
| Endpoint DLP     | Maintain continuous, stable endpoint agent communications and telemetry flow with the central management platform.                                                   | Eliminates blind spots in endpoint monitoring caused by silent agent connection drops or service failures.                                                   |
| Endpoint DLP     | Enforce custom Smart ID detectors on local endpoints to block the exfiltration of cryptographic files and private certificates.                                      | Prevents high-risk breaches involving compromised private PKI keys and certificates directly from user endpoints.                                            |
| Endpoint DLP     | Align endpoint agent installation requirements with existing local antivirus (AV) and host-level security configurations.                                            | Ensures uninterrupted agent performance, prevents endpoint CPU degradation, and avoids security software conflicts.                                          |
| Endpoint DLP     | Establish a structured, monitor-only testing phase before deploying active blocking rules across production endpoints.                                               | Enables the security team to establish behavioral baselines, tune rules, and validate stability before affecting user workflows.                             |
| Web DLP          | Monitor and prevent unauthorized exfiltration of sensitive files and PII via browser-based web uploads.                                                              | Prevents accidental or malicious data uploads to unsanctioned websites, personal webmail, or external job boards.                                            |
| Web DLP          | Prevent exfiltration of sensitive corporate data, source code, or PII through Generative AI (GenAI) prompt text submissions.                                         | Mitigates compliance and intellectual property exposure resulting from employees typing proprietary text into public GenAI platforms (e.g., ChatGPT).        |
| Web DLP          | Mitigate data exfiltration through alternative browser features or side-channels that bypass standard endpoint monitors.                                             | Closes browser loopholes (such as the Microsoft Edge sidebar) before go-live, ensuring a secure browser perimeter.                                           |
| Web DLP          | Restrict administrative and developer portal access through role-based inline authentication and adaptive access controls.                                           | Protects the integrity of the DLP platform's administrative settings and restricts developer portal configurations to authorized roles.                      |
| Web DLP          | Govern browser extension deployments through controlled, enterprise-approved software distribution channels.                                                         | Prevents manual or ad-hoc user installations and ensures a standardized, tested browser-DLP extension across the enterprise.                                 |
| Web DLP          | Ensure resilient, uninterrupted administrator platform access during Single Sign-On (SSO) failures.                                                                  | Provides a secure, vaulted 'break-glass' bypass mechanism for emergency administrators to resolve SAML and SSO certificate issues.                           |

## Output 2: Functional Requirements & Specifications

| Category         | Requirement                                                         | Specification                                                                                                                                                                                                                                                                                                                                    |
|:-----------------|:--------------------------------------------------------------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Email DLP        | Outbound Microsoft 365 User Mail Flow Routing                       | The system must route all outbound user email from Microsoft 365 through the Email DLP pod prior to final internet delivery. This routing configuration is handled by the **DPEML** component.                                                                                                                                                   |
| Email DLP        | Application-Generated and Transactional Email Routing               | The platform must establish dedicated relay routing for application-generated mail flows (AppRelay, UMP) through the Email DLP pod. Handled by the **DPEML** component.                                                                                                                                                                          |
| Email DLP        | Differentiated Rules and Dispositions for User vs. Application Mail | The platform must apply different enforcement rules based on mail type, allowing user-sent mail to be blocked or encrypted, while application-generated mail is set to audit-only or alternate dispositions. Handled by the **DPEML** component.                                                                                                 |
| Email DLP        | Outbound Email Encryption Triggers                                  | The system must trigger the Proofpoint Encryption module based on the subject line keyword (e.g., '[Encrypt]', '[Secure]'), email body, x-headers, or upstream application tags. Handled by the **DPEML** component.                                                                                                                             |
| Email DLP        | DLP-Driven Outbound Message Encryption Tagging                      | The email gateway must accept and act on a DLP-applied header indicating encryption is required, or configure DLP rules to invoke the encryption module directly before delivery. Handled by the **DPEML** component.                                                                                                                            |
| Email DLP        | Domain Alignment and Vanity Senders Processing                      | The email gateway must distinguish between the visible display 'From' header and the envelope sender 'Return-Path' to enforce SPF and domain alignment while allowing vanity display names. Handled by the **DPEML** component.                                                                                                                  |
| Email DLP        | Non-Delivery Report (NDR) and Bounce Routing Mapping                | The gateway must process 500-level fatal errors and route NDRs to the envelope sender 'Return-Path' rather than the display 'From' address, executing notifications within a 3-minute threshold. Handled by the **DPEML** component.                                                                                                             |
| Email DLP        | Active Outlook Gateway Policy Interception (Pause & Protect)        | The gateway must support active interception and holding of outbound emails containing sensitive data ('Pause & Protect'), and integrate with Threat Response Auto-Pull (TRAP) for automated mailbox remediation. Handled by the **DPEML** component.                                                                                            |
| Email DLP        | Legacy Application Port 587 Redirection                             | The system must support legacy email clients on Port 587 by configuring network firewall port-forwarding to redirect Port 587 traffic to standard Port 25 before MTA inspection, maintaining RFC compliance. Handled by the **DPEML** component.                                                                                                 |
| Email DLP        | MTA Real-Time Admin Queue Monitoring                                | The platform must provide real-time administrative visibility into the mail queue to search, filter, and track message status (accepted, queued, or bounced) by return path. Handled by the **DPEML** component.                                                                                                                                 |
| Email DLP        | Cross-Platform Newly Registered Domain (NRD) Policy Tuning          | The system must deploy Proofpoint NRD rules in monitor/audit-only mode, compare detection logs against Microsoft Defender to identify policy overlap, and configure exceptions to prevent redundant blocking. Handled by the **DPEML** component.                                                                                                |
| Cloud DLP (CASB) | DPSPM Cloud Data-Store Scanning with Custom Detectors               | Data Security Posture Management (DPSPM) must run scans on databases and file shares, allowing custom endpoint-created detectors to appear in scan results once the limited-release detector toggle is enabled by the vendor. Handled by the **DPSEC** component.                                                                                |
| Cloud DLP (CASB) | Microsoft Information Protection (MIP) Metadata Reading             | The cloud scanning engine must inspect file metadata and perform exact or keyword matching against MSIP sensitivity labels (MSIP_Label, MSIP_Label_GUID, MSIP_Label_Name). Handled by the **DPSEC** component.                                                                                                                                   |
| Cloud DLP (CASB) | DPSPM Containerized Scanner Deployment                              | The scanning infrastructure must run containerized scanner resources using Podman or Azure sidecar models, requiring specific Azure storage accounts and IAM role approvals. Handled by the **DPSEC** component.                                                                                                                                 |
| Cloud DLP (CASB) | UI Masking of SSO and API Credentials                               | The cloud administration console must mask sensitive Single Sign-On (SSO) configurations, Client Secrets, and Client IDs in the developer portal, and restrict access using custom role-based personas. Handled by the **DPSEC** component (Unified Platform Interface).                                                                         |
| Cloud DLP (CASB) | Entra ID Directory Integration Access Control                       | The system must support identity-only Active Directory integrations by leveraging an Entra ID enterprise application with Directory.Read.All permissions to map user context to cloud events. Handled by the **DPSEC** component.                                                                                                                |
| Cloud DLP (CASB) | Automated Multi-Environment Policy Migration                        | The platform must support validated migration scripts to copy approved configurations (DLP rules, detectors, and dictionaries) from DEV to PAT/PAD to PROD while checking for missing predicates. Handled by the **DPSEC** component (Unified Platform Management).                                                                              |
| Cloud DLP (CASB) | Indexed Document Matching (IDM) for Proprietary Files               | The platform must build high-fidelity detectors by hashing submitted proprietary business files under Proofpoint Digital Assets, using lower-environment test cycles to establish performance limits and file caps. Handled by the **DPSEC** component.                                                                                          |
| Cloud DLP (CASB) | Geofenced Cloud Connectors for O365 Regional Mapping                | The platform must synchronize individual regional Cloud Connectors for Office 365, mapping users to geofenced realms (US1, CA1, Japan, Singapore, EU) to maintain strict data residency compliance. Handled by the **DPSEC** component.                                                                                                          |
| Cloud DLP (CASB) | Cloud Storage File Upload Blocking                                  | The platform must integrate CASB with sanctioned cloud drives (SharePoint, OneDrive) and proxy controls to monitor and block uploads of files containing PII/SINs to unsanctioned apps. Handled by the **DPSEC** component.                                                                                                                      |
| Cloud DLP (CASB) | Continuous Small File Scanning (>0 Bytes)                           | The scanning engine must inspect all file upload payloads larger than 0 bytes to consistently detect sensitive content in micro-files or text snippets, preventing evasion controls. Handled by the **DPSEC** component.                                                                                                                         |
| Endpoint DLP     | Device-Level Print and Folder Activity Monitoring                   | The endpoint agent must log file system I/O to monitored directories (e.g. IT Client Utility folder) and capture printing actions on spreadsheets containing customer SINs. Handled by the **DPSEC** component.                                                                                                                                  |
| Endpoint DLP     | USB and Removable Storage Prevention                                | The endpoint agent must intercept and block copy/move operations of sensitive files to USB/removable media, utilizing the same central data classifiers. Handled by the **DPSEC** component.                                                                                                                                                     |
| Endpoint DLP     | Identity-Driven Rule Scoping for Nested Groups                      | The endpoint policy engine must ingest user attributes via SCIM, API, or OpenID, and enforce policies based on AD nested security group memberships up to 6-7 levels deep. Handled by the **DPSEC** component.                                                                                                                                   |
| Endpoint DLP     | ITM Visual Screenshot Capture Triggering                            | The Insider Threat Management (ITM) module must trigger screen recording and capture screenshots with metadata during high-risk endpoint activities, storing them securely in AWS S3 storage. Handled by the **DPSEC** component.                                                                                                                |
| Endpoint DLP     | Endpoint Activity Exploration Forensics                             | The endpoint agent must continuously feed activity metadata to the console's 'Activity Exploration' view, enabling analysts to inspect user operations regardless of whether an alert rule was triggered. Handled by the **DPSEC** component.                                                                                                    |
| Endpoint DLP     | Interactive Endpoint Justification Prompts                          | The endpoint agent must intercept unauthorized file movement and present an interactive 'Prompt' pop-up window, requiring the user to select or type a business justification before completing the action. Handled by the **DPSEC** component.                                                                                                  |
| Endpoint DLP     | Antivirus Exclusion Path Alignments                                 | The endpoint agent must operate concurrently with local AV software by establishing approved folder, binary, and registry exclusions in the endpoint AV console. Handled by the **DPSEC** component.                                                                                                                                             |
| Endpoint DLP     | Endpoint Active Rule Limit Capacity Escalation                      | The endpoint agent must enforce consolidated rules using multi-condition OR statements to stay under vendor performance thresholds, with escalation pathways to raise the active rule cap to 250. Handled by the **DPSEC** component.                                                                                                            |
| Endpoint DLP     | Automated Agent Heartbeat Recovery Scripting                        | The platform must integrate with the SIEM to alert on agent communication drops (losing heartbeat in the 24-29 day window), triggering an MDM script (e.g. Intune) to forcefully restart the Proofpoint agent service. Handled by the **DPSEC** component.                                                                                       |
| Endpoint DLP     | Custom ITM vs. DLP Event Tagging                                    | The endpoint policy must apply custom tags and response-action tags to policies, ensuring that SOC analysts can filter and distinguish ITM screenshots and behaviors from standard DLP alerts in Splunk. Handled by the **DPSEC** component.                                                                                                     |
| Endpoint DLP     | Staged 'Monitor-Only' Phase Rollout                                 | The endpoint agent must deploy silently to an initial production wave of 100 machines (and subsequently to a 500-user pilot group) in passive monitoring mode with zero active blocking rules. Handled by the **DPSEC** component.                                                                                                               |
| Endpoint DLP     | File Extension Normalization Operator Matching                      | The endpoint policy conditions targeting file extensions must utilize the 'CONTAINS' operator instead of an exact 'IN' match, or specify extension strings without a leading dot to successfully block files (e.g. 'docx' vs '.docx'). Handled by the **DPSEC** component.                                                                       |
| Endpoint DLP     | Smart ID Private Certificate Clipboard Block                        | The endpoint agent must inspect copy-paste/clipboard actions for cryptographic private keys, applying custom Smart ID regex detectors and ensuring the data class is enabled across Realm Settings. Handled by the **DPSEC** component.                                                                                                          |
| Endpoint DLP     | Thick-Client and Managed Application Whitelisting                   | The endpoint agent must monitor file attachments to thick-client software, identifying applications by binary/executable name (e.g., outlook.exe) and comparing them against custom allow/block lists. Handled by the **DPSEC** component.                                                                                                       |
| Web DLP          | Targeted Web Upload Prevention Rules                                | The system must inspect outbound HTTP/HTTPS traffic and block sensitive file uploads to unapproved web destinations (e.g., dlptest.com, personal email, or external web boards) using URL, domain, or TLS domain conditions combined with keyword dictionaries and file size thresholds (e.g., under 500KB). Handled by the **DPSEC** component. |
| Web DLP          | Generative AI (GenAI) Prompt Scanning and Redaction                 | The browser extension must inspect text typed into Generative AI text areas, automatically blocking or redacting sensitive patterns like SSNs or SINs before form submission. Handled by the **DPSEC** component (Browser Extension).                                                                                                            |
| Web DLP          | Alternative Browser Side-Channel Exfiltration Mitigation            | The platform must mitigate data leakage through browser features (such as the Microsoft Edge sidebar) using GPO, Netskope, or browser policies to restrict sidebar utilities if they bypass the DLP agent. Handled by the **DPSEC** component.                                                                                                   |
| Web DLP          | Role-Based Adaptive Access Controls for Portals                     | The platform must deploy Adaptive Access Control policies that block standard, non-admin users from accessing administrative areas, restricting access to the developer portal and tenant settings page to verified administrative accounts. Handled by the **DPSEC** component.                                                                 |
| Web DLP          | Enterprise Browser Extension Deployment Controls                    | The system must prevent ad-hoc browser extension installation in production, deploying approved extensions via GPO, Intune, or MDM, and establishing a secure, non-bypassable QA testing path in lower environments. Handled by the **DPSEC** component.                                                                                         |
| Web DLP          | Emergency SAML Recovery and Break-Glass Local Admin                 | In the event of an SSO certificate signature mismatch, administrators must be able to bypass SAML by using local credentials to manually wipe the SAML setup and upload renewed certificates. Emergency accounts must be vaulted 'break-glass' local super-admins. Handled by the **DPSEC** component (Unified Platform Admin).                  |
